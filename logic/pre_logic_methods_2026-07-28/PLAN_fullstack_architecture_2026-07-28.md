# Plan — full-stack architecture for Torah_Grok

**Date:** 2026-07-28
**Kind:** engineering plan (proposal — implementation starts on owner order)
**Constraint that shapes everything:** the repo's own Pre-Code Logic rule (`AGENTS.md`, `logic/SYSTEM.md`): logic is authored by hand in frozen, reviewable documents; **code may only interpret**. Therefore any database here is a **derived, rebuildable index — never the system of record.**
**Status of prerequisites:** git initialized + pushed to **private** GitHub repo `Josephtorah/Torah_Grok` (2026-07-28, commit `9c59e8b`, 1017 files). `Data/sefx/` gitignored (re-fetchable partial clone of `Sefaria/Sefaria-Export`); `*.sqlite` gitignored by design (derived artifact).

---

## 1. The layer model

```text
SOURCE (git-versioned text, hand-authored, canonical — "the code")
  Data/*.xml, *.json          ← immutable corpora (never written by us)
  logic/taamim_rules/vN/      ← versioned parse rules + golden tests
  logic/units/*.yaml          ← derivations (the source code of the logic)
  logic/TREE_INTERPRETATION_RULES.md, lexicon, role rules (to be versioned)

BUILD (deterministic pipeline — "the compiler")
  parse trees → attach OSHB morph → apply role rules → validate units → index
  same inputs + same rule versions ⇒ byte-identical output

STORE (derived, rebuildable, never hand-edited — "the symbol table")
  one SQLite file (torah_grok.sqlite), regenerated by `make rebuild`

SERVE (read-only — "the frontend")
  HTML reports (current) · web/taamim_tree D3 viewer (next) · query CLI
```

Mental model: a **compiler project**. Corpora = standard library; rules = compiler
passes with versioned releases; YAML units = programs; SQLite = the symbol table an
IDE queries; HTML/D3 = rendered documentation. Deleting the STORE loses nothing.

## 2. Database choice

**SQLite.** Local-first, single file, zero server ops, ships with Python, FTS5
full-text search built in. Scale check: whole Torah ≈ 80k words / ~300k morpheme
segments — a few MB. Full Tanakh + all 312 corpus files still trivial.
**Not** Postgres (nothing gained until this is a multi-user web service). **Not** a
graph DB (a `links` table covers cross-references until graph traversals dominate).

## 3. Schema (v1)

```sql
-- text layer
verses    (id, osis_id, book, chapter, verse, system)        -- prose|poetry
words     (id, verse_id, idx, he, he_plain, translit, lemma, morph,
           mark_id, mark_kind, mark_rank, maqqef_after)
segments  (id, word_id, seg_idx, he, translit, lemma_seg,    -- morpheme level:
           morph_seg, gloss)                                 -- the ו/ה/ל/מ rows

-- structure layer (versioned, mirrors logic/taamim_rules/)
trees     (id, verse_id, rule_version, status, tree_json)
leaves    (id, tree_id, b_index, w_start, w_end, end_mark, rank, path)

-- interpretation layer (versioned)
roles     (leaf_id, role, ruleset_version)                   -- CMD/OBJ_FRAME/…

-- derivation layer (INDEXED FROM logic/units/*.yaml — never authored here)
units     (id, file, book, span, status, last_indexed)
steps     (id, unit_id, step_id, kind, he, translit, en, confidence)
coverage  (unit_id, word_ref, role, tir_id)

-- oral layer
oral_refs (id, work, locus, he_quote, translit, en, tier,    -- verified|observation
           anchors_to)
oral_texts FTS5 (work, locus, he_plain)                      -- all 312 Data files

-- everything searchable
fts       FTS5 over (he_plain, translit, en) across layers
```

Schema rules: every text column keeps the **he + translit + en** triple (the
"never bare Hebrew" rule enforced structurally); every derived row records the
**rule/lexicon version** that produced it.

## 5. What is explicitly avoided

- **Authoring derivations in the DB or via an admin UI** — would silently replace the
  YAML as canon and collapse provenance (the exact v3–v8 failure mode the Pre-Code
  rule exists to prevent). All writes stay in git-reviewed text files.
- **ORM + web framework on day one.** `build_db.py` + stdlib `sqlite3` is the whole
  backend for months. A thin read-only FastAPI only if the D3 viewer outgrows static
  JSON exports.
- **English as authoritative anywhere.** en columns are aid, structurally paired.
- **Public repo with `Data/` inside** — licensing (Standing Decisions §7); repo is
  private, corpora included; if ever public, exclude Data/ and document re-fetch.

## 8. Roadmap to executable logic (added 2026-07-28)

Framing: code never *derives* logic (Pre-Code rule). The end state is code that
**executes** logic a human derived and froze.

```text
✅ Layer 0 — sources:      corpora in Data/ · git + private GitHub
✅ Layer 1 — structure:    v3 ta'amim rules · all 5,853 verses parse unique
✅ Layer 2 — morphology:   OSHB joined, morpheme-level, whole Torah
🟡 Layer 3 — role hints:   whole Torah, shallow (r0 heuristics; '?' outside Gen-1 lexicon)
🟡 Layer 4 — derivation:   34 verses hypothesis-tier (week experiment doc)
                           + ~190 tree_derived_v1 DRAFT units (pre-roles)
❌ Layer 5 — frozen logic: no unit upgraded with the new logic yet
❌ Layer 6 — interpreter:  no code executes any of it yet
```

|-------|------|-----|-----------|
| **A — harden mechanical layers** | lexicon + role rules → versioned files (`logic/lexicon/v1*`, `logic/role_rules/v1*`) with goldens; grow lexicon whole-Torah (EN-AID, #IMPOSED-labeled source); DB steps 2–3 (index units; oral_refs + oral_texts FTS with citable loci) | agent | no `?` glosses; units + Oral queryable |

| **C — derive units to frozen** | per unit: full `binary_trees` + 100% coverage + derivation log A–J *including logic lines* + scenarios + named Oral + confidence → `status: frozen`. Pilot: day 1 (Gen 1:2–5); then the week; then Leviticus (casuistic payoff) | owner+agent (the long middle — this IS the project) | per unit: frozen, with scenarios |
| **D — the interpreter** | the dry-run machine as a program: loads FROZEN units only, executes logic lines against registers (TIME/WORLD/REGISTRY/SPECS/TESTS/LEDGER), runs scenarios as assertions. Same contract as parser: never invents; red scenario ⇒ fix document or version the rulebook | agent | hand-trace of Gen 1:1–10 reproduces mechanically |

predicts it: machines do structure + verification at scale; deciding what the Hebrew
*means* stays in reviewable documents.
