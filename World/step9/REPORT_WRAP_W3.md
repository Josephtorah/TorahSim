## THE PARSER'S HOMOGRAPH — three functions that write nothing

The gate's function parse reads every registered-effect-named string in a function's source as an effect it
writes. Three W3 functions had NO honest effect (every cell FX.NONE) and were on the worklist only because a
string in their source is spelled like an effect: cold_run_chatat.identity and .sprinklings carry the TIER NAME
'anointed' (`who == 'anointed'`, `tier in ('anointed', 'congregation')`); cold_run_minchah.oil_ops carries the
cell VALUE 'anointed' (Lev 2:4's wafers anointed with oil). A daemon that wrote `anointed` to satisfy the gate
would be lying. They are declared NONE with the why, and the parser's looseness is recorded OPEN in
COMPILE_DEBT as a gate item (its own sitting: read effects from the cells' fx lists, then remeasure the 251).
The census script that found them (scratchpad w3_census.py) put the loose set beside the honest set for all
61 functions; five more carried the homograph beside honest effects (blood, carcass, fat, sliding_scale_by_tier,
timing; resolution's 'buried' a dict value) — wrapped by their honest effects, no harm.

## Findings (none seat: no unit touched)

1. **THE PARSER'S VALUE/EFFECT HOMOGRAPH** (above): three NONE, one OPEN gate item.
2. **THE TAPE PARSER READS ONLY A LITERAL KIND.** A submit built as dict(base, ...) or dict(kind, ...) is
   '?UNRESOLVED?' to the gate — it fired six ways on the first run (an unregistered kind submitted, three
   watched kinds "on no tape", one unconsumed) until the fourteen submits were rewritten with the literal
   `'kind': '...'` inside the braces. The gate was right: it could not see the kind; the fix is the tape's, not
   the parser's.
3. **A NEW TOP-LEVEL DEF THAT COUNTS IS A LAW TO THE GATE.** scene_wrap() in the eighth-day runner was read as a
   compiled function with no disposition; folded into scene() (the INFRA name), the count returned beside the
   old tuple.
4. **THE PROBE CAUGHT THE COLON.** The eighth day's spec strings 'olah: as prescribed' and 'minchah: the palm
   filled' carry the colon on the head word; the head test matched 'chatat' and 'shelamim' and missed those two
   — the probe printed 0 where the prediction said 1, and rstrip(':') fixed it before a literal was typed.
5. **A TUPLE MUST COUNT WHAT THE DAEMON WRITES.** The minchah tuple asked the todah-bringer for the loaves'
   acceptance; the daemon writes it on the loaves. The probe printed 0; the entity was corrected, not the code.
6. **THE SCORE LINE IS NOT THE EXIT CODE.** vayikra5's effects section called a string method on the scene
   row's tuple after "MATRIX: 32/32" had printed; the sweep reads both. Guarded with isinstance.
