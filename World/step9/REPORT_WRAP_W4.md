## Findings (none seat: no unit touched)

1. **A NESTED MACHINE IS UNREACHABLE.** negaim's TRACKS, days(), standing_verdict() and house_machine() lived inside
   main(); a daemon cannot call a nested function. Hoisted to module level, the verdicts and the ten-houses walk
   unchanged, the guard count unchanged (the hoisted names carry no effect string, so the gate reads no new law).
   The other main()-style runners on W5-W7's list (holiness, sanctions, tochacha, yovel) may carry the same shape.
2. **THE GUARD'S LAST-BINDING RESOLUTION, SIDESTEPPED NOT FIXED.** Adding a fifth `grade()` call in negaim with the
   cells bound to `cells` would have counted 10 + 5 × 1; naming the list `scene_cells` kept the old count and added
   one. The OPEN gate item stands as recorded.
3. **THE PROBES MATCHED FOUR FOR FOUR.** The first sitting where no probe disagreed with its prediction — the
   predictions were written into the record before the runs (15/13/82; 36/36/20; 2/2/9; 4/4/11).
4. **THE PARENTHESIS.** One syntax fault in the yoma daemon caught by fix_percent's parse before any run — the
   standing order to run it on every edited runner paid for itself in the ordinary way.

## Lessons banked

- Predict, print, compare: writing the expected tuple into the sitting's notes BEFORE the probe is what made the
  four matches evidence rather than coincidence.
- A text event that voids a clock is a cancel, not a rewrite: the daemon cuts the timer and the new stop sets it
  again; the log keeps all four records.
- A statute written twice is one type with two consumers; the field contract grows by extension, never by a second
  contract.
- A main()-style runner takes its scene at module level and grades it inside main() — measure the guard, then set
  the literal.
